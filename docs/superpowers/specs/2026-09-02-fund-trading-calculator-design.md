# 基金入出仓资金测试页设计

## 目标

新增独立 `/t-calculator` 页面，模拟东方人工智能主题混合 C（017811）的分批入仓、补仓、确认加仓和分批出仓，实时展示现金、持仓市值、账户总资产、平均成本、回本净值和回本涨幅。页面只做本地计算，不请求基金行情，不修改现有首页或用户持仓数据。

## 设计方向

采用“交易实验台”视觉：复用项目现有深蓝/亮色主题变量、青色主色和涨跌语义色，使用紧凑的参数面板与可横向滚动的资金流水表。桌面端采用参数区与结果区双栏布局，移动端改为单列；数字使用等宽字体增强比对感，但正文沿用项目字体系统。

## 页面结构

1. 页面头部：基金名称、代码、数据说明、恢复默认值按钮。
2. 参数面板：本金、基准净值、模拟净值、赎回费率、持有天数；输入项全部带可见标签和约束提示。
3. 入仓阶梯：每行包含名称、相对基准跌幅下拉选择、投入金额和收益率；默认 2000/1500/2000/1500/3000 元方案。最后一档为止跌确认加仓，可手工输入净值。
4. 出仓阶梯：每行包含相对上一轮净值的涨幅下拉选择、当前剩余份额比例和动作；默认连续上涨 10% 三轮，每轮卖出当前剩余份额 10%。
5. 结果卡片：当前模拟净值下的现金、持仓市值、账户总资产、累计盈亏、平均成本、回本净值和回本所需涨幅。
6. 流水表：分别展示每个入仓节点和出仓节点后的现金、持仓份额、持仓市值、账户总资产、累计投入/已实现现金与回本数据。
7. 情景快捷操作：将模拟净值设为基准净值的 60%，展示回撤 40%后的资金和回本要求；提供恢复按钮。
8. 颜色语义：入仓金额显示绿色 `+`，出仓金额显示红色 `−`，收益率正值绿色、负值红色。

## 计算规则

- 每次买入份额 = 买入金额 / 当次净值。
- 持仓均价 = 累计投入 / 累计份额。
- 持仓市值 = 累计份额 × 模拟净值。
- 账户总资产 = 剩余现金 + 持仓市值。
- 不计赎回费时，回本净值 = 持仓均价；计赎回费时，回本净值 = 持仓均价 / (1 - 赎回费率)。
- 出仓按上一轮触发净值连续计算涨幅，再按当前剩余份额比例执行，避免把“卖出 10%份额”误算为初始仓位的固定现金。
- 负数、空值、非有限数字和负金额不参与计算，并在输入附近显示错误提示。
- 计算模块保持纯函数，不读写 localStorage，不影响真实基金持仓。

## 文件边界

- `app/t-calculator/page.jsx`：客户端页面状态、表单、结果展示和交互。
- `app/t-calculator/calculator.mjs`：纯计算函数和默认配置。
- `app/t-calculator/calculator.check.mjs`：基于 Node 内置 `assert` 的最小可运行计算检查。
- `app/t-calculator/calculator.module.css`：页面局部样式，优先复用全局主题变量，并由 Next.js CSS Modules 负责作用域隔离。

不修改 `app/page.jsx`、现有 Zustand store、外部 API 和现有持仓数据。

## 验证标准

- 默认数据下，入仓流水与手工计算一致：下跌 18%节点累计投入 7000 元、剩余现金 3000 元、账户总资产约 9312 元、平均成本约 2.9775。
- 回撤 40%情景显示资产为本金的 60%，回本需要上涨 66.67%。
- 出仓流水能区分累计现金、剩余持仓市值和账户总资产。
- `node app/t-calculator/calculator.check.mjs` 通过。
- `npm run lint` 通过；不运行完整 build，除非用户明确要求。
- 浏览器验证桌面端和移动端，检查输入键盘路径、长表格滚动、无效输入提示和快捷情景按钮。

## 明确不做

- 不接入实时基金估值或交易 API。
- 不自动执行买入、赎回或写入真实持仓。
- 不新增图表库、状态管理或后端接口。
- 不改现有首页布局。
