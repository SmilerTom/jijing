# 单基金 T 交易看板与风控设计

## 背景

现有页面已支持单只基金的入仓、出仓金额录入、按发生日期补全基金净值、自动计算份额与流水结果。本次把它收敛为一个面向日常做 T 的基金看板，解决“基金净值未更新时如何判断”“指数能否提前预警”和“入出金后盈利率口径不一致”等问题。

## 目标

- 用一个交易驾驶舱展示当前持仓、账户盈利、回本净值和风控状态。
- 通过一个“＋”入口选择入金或出金，保持金额优先的操作流程。
- 流水统一展示时间、日涨跌幅、金额、累计金额、收益率。
- 同时展示基金实际净值和官方业绩比较基准中的指数成分；本基金资料标注为“无跟踪标的”，因此页面使用“业绩基准指数参考”这一准确名称。
- 根据基金日涨跌、指数涨跌和最大回撤生成分级提醒。
- 基金净值未更新时明确显示待更新，不用指数值替代基金实际计算。

## 非目标

- 不自动提交基金交易或代替用户确认金额。
- 不保证收益最大化；规则只用于纪律化提示和结果复盘。
- 不把跟踪指数当作基金净值、份额或账户实际收益。
- 本次不扩展多基金组合、税费、外部券商交易接口。

## 页面结构

1. 顶部账户总览：持仓市值、持仓份额、账户盈利率、回本净值、最大回撤、风控状态。
2. 今日行情卡片：基金净值、前一交易日净值、基金日涨跌幅、业绩基准指数参考名称、指数涨跌幅、数据更新时间和状态。
3. 操作入口：右上角一个“＋”按钮，菜单包含“入金”和“出金”，共用金额和发生时间字段。
4. 风控提示条：按严重程度显示观察、建议补仓、建议出仓或暂停补仓；指数触发时标注“指数预警”。
5. 入仓/出仓流水：表头统一为“时间、日涨跌幅、金额、累计、收益率”，保留份额、持仓市值、总资产、净值等核算列。

## 数据与计算口径

- 基金日涨跌幅 = 当日基金净值 / 前一交易日基金净值 - 1。
- 账户总资产 = 当前持仓市值 + 累计出金净额。
- 账户盈利率 =（账户总资产 - 累计入金）/ 累计入金。
- 流水节点收益率用于表达该节点计算后的资产表现；它与账户盈利率不保证相同，尤其在多次入金、出金后。
- 最大回撤 = 当前账户总资产 / 历史账户总资产高水位 - 1。
- 业绩基准指数参考涨跌幅仅作实时预警参考，基金净值更新后仍以基金实际净值为准；本基金资料中的指数权重为 80%，其余 20% 为银行活期存款利率。
- 出仓金额先按当日基金净值反算卖出份额，再更新累计出金、剩余份额和持仓市值；入仓金额按当日基金净值换算买入份额。
- 当基金净值为空、无效或请求失败时，日涨跌幅、节点收益率和相关风控计算显示待更新/获取失败，不回退为 0%。

## 风控与提醒

默认规则可编辑：

- 基金日跌幅 -5%：观察；-8%：建议补仓；-12%：强提醒。
- 基金日涨幅 +5%：观察；+8%：建议出仓；+12%：强提醒。
- 最大回撤 -10%：风险提醒；-20%：限制继续补仓并显示回本净值。
- 业绩基准指数参考达到相同阈值时生成“指数预警”，不直接修改基金实际收益。
- “今日净值未更新”作为独立状态提醒，避免用户把旧数据当作今日数据。
- 页面内提醒默认开启；系统通知开关默认关闭，开启时由浏览器自行申请权限。
- 同一规则同一交易日只显示一次有效提醒，手动刷新不会重复堆叠提醒。

## 异常与可用性

- 基金接口失败：显示“基金净值获取失败”，保留已录入流水，不清空用户输入，并允许重新获取。
- 指数接口失败：显示“业绩基准指数暂不可用”，基金实际计算继续独立运行。
- 数据日期不一致：显示各自的更新时间和来源，不合并成一个涨跌幅。
- 所有金额输入支持清空、非负校验和两位小数；盈利率允许负值。
- 操作入口、风控提示和输入框具备可访问名称、键盘操作和可见焦点。
- 移动端保持看板卡片可读，流水表格允许横向滚动且页面本身不横向溢出。

## 验证标准

- 纯计算检查覆盖多次入金、出金金额反算份额、累计盈利率、最大回撤和净值待更新状态。
- 浏览器检查覆盖：页面加载无控制台错误；“＋”菜单可选择入金/出金；基金净值未更新时不误触发；指数预警与基金实际收益分开显示；输入金额后流水自动更新；移动端布局可用。
- 完成后运行聚焦检查、ESLint 和 git diff --check；不默认运行完整构建。
